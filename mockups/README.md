# KPI 지표형 · AI 분석 강조 견본 (브랜치 `mockups/kpi-ai-2026-11`)

본 화면(`../index.html`)과 분리된 탐색용 견본입니다. 본 화면의 배치 · 색 · 글꼴은 참고하지 않았고, 데이터 구조(fetch 경로 · 필드 이름)만 확인했습니다.

## 여는 방법

저장소 루트에서 정적 서버를 띄우고 `mockups/index.html`(20개 비교 목록)을 엽니다.

```bash
python3 -m http.server 8000
```

`http://localhost:8000/mockups/` → 목록 · 견본 링크. 견본은 `../games.json`, `../data/lostark.json`, `../data/lostark-daily.json`, `../data/lostark-monthly.json`을 상대 경로로 읽습니다(파일을 직접 열면 브라우저가 fetch를 막습니다).

## 조사의 한계

이 작업 환경은 네트워크 정책으로 외부 웹페이지 열람이 막혀 있었습니다. 그래서 **출처 120건 모두 '검색 결과만'**(열람 0건)이고, 분류 값은 검색 결과 문장에 나온 낱말로만 판정했습니다(근거 없으면 '확인 불가'). 실제 화면을 보고 확인한 것이 아닙니다.

## 확인한 것 (2026-10-31, 헤드리스 Chromium)

- 20개 견본 + 목록 모두: 콘솔 오류 0 · 페이지 오류 0 · 실패한 요청 0, 데이터 파일 4개 모두 200으로 읽힘, 렌더 완료 신호 확인, 390px에서 가로 넘침 없음.
- 버튼 · 탭 · 선택 상자를 눌러 보는 자동 점검: 처음에 08 · 12 · 17에서 'AI 판단 초안이 없는 주'(2026-09-21 이전 국내 후보, 2026-08-17 해외 후보)로 옮기면 오류가 났고 고쳤습니다. 다시 돌린 결과 오류 0.

## 확인하지 못한 것 · 알아 둘 점

- 사람이 직접 마우스로 써 본 것이 아니라 자동 클릭 점검입니다. 모든 조합(지역 × 주 × 필터)을 다 눌러 본 것은 아닙니다.
- 인쇄(10) · 클립보드 복사(10) 결과, 실제 큰 화면에서의 장면 전환(11)은 확인하지 못했습니다.
- 모든 견본이 같은 데이터 읽기 코드를 써서 `lostark-daily.json` · `lostark-monthly.json`도 함께 요청합니다. `plan.json`의 `data_files`는 실제로 화면에 쓰는 파일만 적었습니다.
- 13(불릿 점수표)의 주제 비중 경보선 '평시 + 1.25σ'는 데이터의 z와 값에서 거꾸로 계산한 참고선이고 화면에 그렇게 적었습니다.
- 19(AI 장부)의 주별 모델 건수는 데이터에 '어떤 글이 재분류됐는지' 구분이 없어 모델별 기록 건수로만 표시했습니다.
- 감성 정확도의 표본은 데이터상 99건이어서 99로 표시했습니다(주제 · 의견 유형은 100건).
- 18(메신저 다이제스트)의 구독 시각 '수요일 09:00'은 '예시 값'으로 표시했습니다. 그 밖의 숫자는 모두 데이터에서 왔습니다.
